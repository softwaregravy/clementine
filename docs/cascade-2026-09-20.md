## The decisions, on one screen

`DECISIONS.md` is binding; this is the map from decision to doc.

- **Scope:** every violation the city says is owed on the plate counts — parking was the *minimum* scope, not a ceiling. **No classification of any kind** in Phase 1: no camera filter, no blocklist; `violation` and `issuing_agency` are not read. Camera-specific *features* (dispute handling, camera deadline math) stay out; camera *rows* do not. Copy says **"tickets", never "parking tickets."** (DEC-065; DEC-002 and DEC-038 superseded; DEC-066–068 struck.)
- **Open predicate:** `amount_due` is carried as the API's string and never cast. Open ⇔ present, non-empty, not `"0"`. Anything unrecognized counts as open and logs WARN. Any amount owed is owed — a penny balance is one open ticket. (DEC-064; DEC-037 superseded.)
- **Outcomes and sends:** Clean → silence. Count → Digest. **Uncertain and Unreachable → silent to the subscriber, ERROR in the log, and the rake task exits non-zero** so the run shows as failed in Render. System failures alert the maintainer, never the user. **No Alert send. Two send types: Welcome and Digest.** (DEC-071, DEC-077; DEC-029 superseded for Phase 1; DEC-041 amended.) Invariant 1 now means: a broken read is never *recorded* as Clean and never produces a digest; to a subscriber, Uncertain looks like Unreachable — silence — and "silence means clean" becomes "silence means clean, or the system is broken and John knows."
- **Drift:** a run-level check in the summary line, not per-row logic: `rows > 0` with no row carrying `amount_due` → ERROR; any key outside the 19 published columns → ERROR. Sparse rows (no `amount_due`) stay not-open, skipped, WARN residue. (DEC-069; DEC-039 amended.)
- **Fetch:** one attempt per plate, 10 s timeout, **no retries**; `$limit=5000`, and a response of exactly 5,000 rows → Uncertain. No canary. Per-plate isolation. (DEC-070, DEC-072, DEC-074; DEC-052's retry model and amendment A1 superseded.)
- **Logs only, one table.** One JSON line per plate outcome (subscription id, plate, state, outcome, reason code) plus a run summary (outcomes, sends, duration, `rows`, `rows_with_amount_due`, `rows_without_amount_due`, `unknown_keys`). Levels: INFO routine; WARN residue skips, unrecognized `amount_due` strings, Twilio 21610 on a send; ERROR Uncertain and Unreachable. Never a phone number. (DEC-073, DEC-078; DEC-045 decided in corrected form.)
- **Schema:** `subscriptions(phone E.164, plate, state, timestamps)`, unique on `(phone, plate, state)`. **No nickname.** No `active` flag — console removal is destroy; STOP is Twilio's, surfacing as error 21610 at send time. Database check constraints on `plate` and `state`, exact patterns fixed at implementation (the data contains `state = "99"`). (DEC-075, DEC-076; DEC-013 amended.)
- **Process:** P1–P20 and amendments A2–A4 accepted as written (cron 14:00 UTC; welcome sends synchronously from the console; fixture-first with WebMock; GitHub Actions; trunk-based; env-var secrets; dev + prod only). (DEC-078.)
- **Twilio:** no account exists yet; account → local NYC number → A2P 10DLC (sole-proprietor) is step zero and runs in parallel with the build. Two sample messages. (DEC-079.)
- **Accepted, named risks:** sustained-outage silence and empty-dataset silence (DEC-081, DEC-074); small balances count (DEC-064); a ticket under dispute counts (`HEARING PENDING` carries a balance — open-questions C3); plate collisions across license types (C2); SODA 2.1 deprecation (C1).
- **Closed by live probes** (DEC-080): judgment rows keep `amount_due` as the net balance with interest (cents appear); `$limit` above 1,000 works; the 19-column list is confirmed; CityPay has no plate-prefill URL — the digest links to the landing page.
